# SPEC 02 — Camada de IA

## Regra
A IA faz **uma coisa só**: transformar entrada humana (arquivo ou frase) em
`Tx[]`. Ela não calcula, não aconselha, não conversa. Todo veredicto financeiro
é aritmética em `budget.ts` (SPEC 03) e custa zero token.

Isso não é economia estética: um "posso gastar R$200?" via LLM custaria token a
cada pergunta e ainda erraria conta. Como função pura, custa nada e não erra.

## Modelo
`claude-haiku-4-5` — o mais barato da linha ($1 / $5 por milhão de tokens),
200K de contexto, lê PDF e imagem. Definido em `MODEL` (`src/ai.ts`), um lugar só.

## Chamada
Uma função, `extract(input, settings)`. `input` é `{ text }` ou
`{ base64, mediaType, name }`. HTTP direto (`fetch`) porque o SDK oficial
assume Node/browser e o app roda nos dois + React Native; a chamada é um POST só.

O SDK oficial (`@anthropic-ai/sdk`) fica em `devDependencies` e entra **só como
tipo** (`import type`): ele importa `node:fs` na cadeia de credenciais e não
empacota no Metro para iOS/Android. `import type` some na compilação, então o
runtime é `fetch` puro e o request continua tipado pelo SDK oficial.

- Endpoint: `POST https://api.anthropic.com/v1/messages`
- Headers: `x-api-key`, `anthropic-version: 2023-06-01`, e na web
  `anthropic-dangerous-direct-browser-access: true` (sem ele o CORS barra).
- PDF: bloco `{type:'document', source:{type:'base64', media_type:'application/pdf'}}`
- Imagem: bloco `{type:'image', source:{type:'base64', media_type:'image/jpeg'|...}}`
- Saída estruturada: uma tool `salvar` + `tool_choice:{type:'tool',name:'salvar'}`.
  Forçar a tool garante JSON válido já parseado em `content[].input` — sem regex,
  sem `JSON.parse` de texto solto.

## Contrato da tool `salvar`
```jsonc
{
  "kind": "invoice" | "bill" | "payslip" | "manual",
  "dueDate": "YYYY-MM-DD",   // fatura/conta: vencimento. contracheque: data do pagamento. manual: omitir
  "items": [{
    "type": "expense" | "income",
    "date": "YYYY-MM-DD",
    "amount": 123.45,         // positivo
    "description": "texto curto",
    "category": "<enum>",
    "installment": "3/12",    // opcional
    "recurring": true         // opcional
  }]
}
```

`CATEGORIES` (enum fechado no schema, para a saída ser somável):
Moradia, Mercado, Alimentação, Transporte, Saúde, Educação, Lazer, Compras,
Assinaturas, Serviços, Impostos, Salário, Renda extra, Outros.

## Custo por operação (Haiku 4.5, ordem de grandeza)
| Operação | Entrada | Custo |
|---|---|---|
| Despesa em texto | ~400 tok | < R$ 0,01 |
| Fatura PDF 4 páginas | ~6k tok in / 2k out | ~R$ 0,06 |
| Contracheque | ~2k tok | ~R$ 0,02 |
| Conta de água/luz | ~2k tok | ~R$ 0,02 |

## Decisões que cortam token
- Prompt de sistema curto (< 200 tokens), em PT-BR, sem exemplos few-shot.
- Sem prompt caching: o prefixo tem menos de 1024 tokens, o mínimo cacheável —
  ligar cache aqui só adiciona custo de escrita.
- **Contracheque grava só o líquido** como uma entrada. Gravar bruto + descontos
  contaria a mesma grana duas vezes.
- **Conta/boleto grava só o total.** Água + esgoto + taxa de serviço são o
  detalhamento de um pagamento só; o prompt manda ignorar leitura de medidor,
  histórico de consumo e código de barras.
- `max_tokens` por tipo: 1024 para texto, 8000 para arquivo (fatura longa).
- Nenhuma chamada é feita sem ação explícita do usuário. Sem polling, sem
  sugestão automática, sem "analisando…" em background.

## PDF protegido por senha
Fatura de banco vem criptografada. Mandada como está, a API recebe bytes
ilegíveis: erro incompreensível e token gasto à toa.

`isEncryptedPdf()` procura `/Encrypt <ref>` ou `/Encrypt <<` no arquivo **antes**
de montar o request e barra com uma mensagem que diz o que fazer. Custo zero,
nenhuma chamada de API. É **fail-open** de propósito: se o `atob` falhar ou o
padrão não bater, deixa passar — barrar um PDF bom é pior do que gastar um
centavo num PDF ruim.

### Por que o app não decripta
Decriptar exige o Standard Security Handler (MD5+RC4 para R2–R4, AES-128/256 para
R4–R6) mais um parser de objetos PDF: ~300 linhas de cripto artesanal, o pior
lugar possível para escrever código próprio.

A alternativa pronta é `pdfjs-dist`, medida em 27/08/2026: **1,6 MB** minificado
(448 KB de API + 1,2 MB de worker) contra um bundle de app de 1,6 MB — dobraria o
tamanho — e depende de `DOMMatrix` e `OffscreenCanvas`, que não existem no React
Native. Descartada.

**Caminho de saída oferecido:** o picker aceita `multiple: true` e a API recebe
vários blocos de documento/imagem numa chamada só, então prints das páginas
resolvem. O prompt avisa que vários arquivos podem ser páginas do mesmo documento,
para não duplicar lançamento.

**Quando revisitar:** se surgir uma lib de decriptação puro-JS abaixo de ~100 KB
sem dependência de DOM, ou se o app passar a ter um build só para web.

## Confirmação obrigatória
`extract()` **nunca** grava. Devolve `Tx[]` para a tela mostrar em preview; só o
toque em "Salvar" persiste. LLM erra valor e data; dinheiro errado gravado sozinho
é pior do que não ter o recurso.

## Erros
Chave ausente → mensagem pedindo para configurar em Ajustes (sem chamar a API).
401/429/500 → mensagem crua da API na tela. Sem retry automático: retry silencioso
gasta token do usuário sem ele saber.
